# Qwen 3B PPO memory comparison — 2026-11-15

## Setup

- GPU: NVIDIA GeForce RTX 4060 Ti, 8,188 MiB dedicated memory reported by `nvidia-smi`.
- OS and driver: Windows, NVIDIA 610.88 (WDDM).
- Python 3.11.14; PyTorch `2.14.1+cu130`; Transformers `5.23.0`; PEFT `0.21.3`.
- Model: `Qwen/Qwen2.5-3B-Instruct`, BF16, cached locally and loaded offline.
- LoRA: rank 16, alpha 32, `q_proj` and `v_proj`.
- Synthetic tokenizer output: batch size 2, sequence length 16. `max_length=256` is a cap, not the actual length.
- Each arm ran in a fresh process. The baseline was repository commit [`6308671`](https://github.com/Bender1011001/ppo-vram-halver/commit/6308671f0f538627e459dc658b3ce4259a819d5a); the revised arm is the code shipped with this report.

## Results

| Source | Separate actor + reference | Shared base, dual pass | Within-source reduction |
| --- | ---: | ---: | ---: |
| Original `6308671` | 12,215.09 MiB | 6,185.26 MiB | 6,029.83 MiB (49.36%) |
| Revised | 12,174.53 MiB | 6,174.98 MiB | 5,999.55 MiB (49.28%) |

The original dual-pass arm returned 6,185.26 MiB on two runs. The revised verifier returned 12,174.53 MiB and 6,174.98 MiB on repeated runs and passed its 35% threshold. The revised dual-pass arm used 10.28 MiB less (0.17%) than the original in this setup. This is a small memory improvement; the approximately 6,000 MiB actor/reference difference was already present in the original code.

The final revised run completed after `torch.cuda.synchronize()` in both arms. The script uses `torch.cuda.max_memory_allocated()` minus the allocation at the start of each arm. This is a PyTorch tensor allocation metric, not a physical dedicated-VRAM residency measurement. [Windows WDDM can page graphics allocations beyond dedicated memory](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/paging-video-memory-resources), including [CUDA allocations](https://forums.developer.nvidia.com/t/does-cudamalloc-increases-the-private-bytes-used-on-host/45797/8). This explains how the separate-model run can report more than 8GB on this card without failing.

## Reproduce

Install a CUDA-enabled PyTorch build and the dependencies in the README, then run:

```bash
python benchmark_rlhf.py --model_name Qwen/Qwen2.5-3B-Instruct --step standard
python benchmark_rlhf.py --model_name Qwen/Qwen2.5-3B-Instruct --step dual_pass
python tests/verify_rlhf.py
```

The original code can be checked out at `6308671`. The benchmark's rollout log probabilities, advantages, returns, and old values are random placeholders, so these results say nothing about PPO convergence, reward quality, or training speed. The historical figures in the original README were not accompanied by raw logs; this report records a fresh comparison on the same machine and environment.
